# Shiftle — iOS handoff

Everything below is ready in this repository. What remains is the part that
needs a Mac, Xcode and an Apple Developer account.

## What Shiftle is

A block puzzle on a round board. You drag arcs, wedges and curved bricks onto a
disc of rings and sectors; filling one whole ring makes it pop. The one special
move is spinning a ring by a single sector, which needs no wrap-around rule to
explain because a ring has no edge. Spins are earned by clearing and act as
lives: the round only ends when nothing fits *and* no spins remain.

Two modes. **Daily** derives its board, piece pack and sequence from the UTC
date, so every player in the world gets the identical puzzle — one attempt per
day. **Free play** lets you pick the disc and pack.

## Key facts

- **Bundle ID**: `com.nomarcus.shiftle`
- **Display name**: Shiftle
- **Xcode project**: `ios/App/App.xcodeproj`
- **Orientation**: portrait only
- **Capacitor 8** — dependencies come from **Swift Package Manager**, so there
  is **no `Podfile` and no `pod install`**. Xcode resolves packages on open.
- **No network access at runtime.** The whole game is bundled. Nothing is
  collected, stored remotely, or tracked.
- `ITSAppUsesNonExemptEncryption` is already set to `false`, so TestFlight
  will not ask about export compliance on each upload.

## Build steps

```bash
git clone https://github.com/Nomarcus/Puzzle.git
cd Puzzle
git checkout claude/simple-puzzle-game-iphone-ho2201
npm ci
npm run ios:sync      # vite build + cap sync ios
npx cap open ios      # or: open ios/App/App.xcodeproj
```

The compiled web bundle is committed at `ios/App/App/public/`, so the Xcode
project will build even without running the Node steps. Run `npm run ios:sync`
whenever the web source changes.

In Xcode, on the **App** target:

1. **Signing & Capabilities** → set your Team; let Xcode manage signing.
2. Set **Marketing Version** and **Build** (currently `1.0` / `1`).
3. Select **Any iOS Device (arm64)** → **Product ▸ Archive** → **Distribute App**
   → **App Store Connect** → **Upload**.

## Game Center

The code is wired but inert until the capability exists — every call no-ops
when the plugin is absent, which is why the web build still runs.

1. In Xcode: **Signing & Capabilities ▸ + Capability ▸ Game Center**.
2. In App Store Connect, create two leaderboards with exactly these IDs:
   - `com.nomarcus.shiftle.daily`
   - `com.nomarcus.shiftle.endless`
3. Install a Game Center bridge plugin exposing `Capacitor.Plugins.GameConnect`
   with `signIn`, `submitScore({ leaderboardID, totalScoreAmount })` and
   `showLeaderboard({ leaderboardID })`. See `src/platform/gamecenter.ts` — the
   interface it expects is at the top of the file.

Leaderboards are optional for a first TestFlight build. Skipping them changes
nothing else.

## Where things live

```
src/engine/     pure game rules — no DOM, no Math.random, fully testable
src/render/     canvas drawing: the disc, the candy bevel, the tray
src/input/      the two gestures (drag to place, drag on the disc to spin)
src/ui/         screens, menus, the animation loop
src/platform/   storage, haptics, share, Game Center — all no-op on the web
tools/          bot, balance sweeps, browser tests, icon generation
ios/            the Xcode project
```

`npm test` runs the engine tests, `npm run play` drives the real game in a
headless browser at iPhone size and writes screenshots to `tools/out/`.
